# AI Abaya Size Engine — محرّك مقاسات العبايات بالذكاء الاصطناعي

منتج مستقل قابل للتركيب في أي متجر عبايات (Shopify / Salla / Zid) يعطي العميلة
**توصية مقاس دقيقة لكل عباية على حدة** — لا مجرّد جدول مقاسات عام.

الفكرة الأساسية: بعد الحصول على قياسات جسم العميلة (بالكاميرا أو يدويًا)، نطبّق
خوارزمية خاصة بالعبايات تقارن القياسات بـ**بيانات العباية نفسها** لتخرج بـ:

> **مقاسك المثالي: 56 — Medium**
> دقة التوصية: 92% · عند الصدر: مريح · عند الورك: واسع قليلًا
> يلامس الأرض → 58 · مع كعب → 58 · أقصر قليلًا → 56

هذا المستودع نسخة أولى (MVP) عاملة بالكامل: محرّك + واجهة عميلة + لوحة تاجر + API + نسخة ملف واحد.

## 🚀 التشغيل السريع

```bash
cd abaya-size-engine
npm install
npm start           # يشغّل الخادم على http://localhost:4100
```

- المتجر التجريبي + أداة العميلة: `http://localhost:4100/`
- لوحة التاجر (إدارة الكتالوج): `http://localhost:4100/merchant.html`
- **بدون خادم إطلاقًا**: افتحي `standalone.html` مباشرة في المتصفح.

```bash
npm test               # اختبارات محرّك المقاسات
npm run smoke          # اختبار متصفح حقيقي للرحلة كاملة (Chromium)
npm run build:standalone   # إعادة توليد standalone.html من المصدر
```

## 🧭 رحلة العميلة

زر داخل صفحة المنتج: **✨ حددي مقاسك بالذكاء الاصطناعي** → تفتح الأداة:

1. **القياسات** — ثلاث طرق:
   - **📷 مسح بالكاميرا**: تُدخل طولها → صورة أمامية → تستدير ٩٠° → صورة جانبية → «جاري التحليل…».
   - **✍️ إدخال يدوي**: طول + (اختياري) كتف/صدر/ورك/ذراع.
   - **⚡ تقدير سريع**: طول فقط (+ صدر/ورك اختياريًا) والباقي يُستنتج.
2. **التفضيلات** — الطول المفضّل (قياسي / يلامس الأرض / مع كعب / أقصر) والقصّة (ضيّقة / عادية / واسعة).
3. **النتيجة** — المقاس المثالي + نسبة الدقة + قراءة الراحة عند الصدر والورك + بدائل الطول.

> 🔒 **الخصوصية**: لا تُرفع ولا تُحفظ أي صورة جسم. الأداة تتعامل مع **أرقام القياس فقط**.
> في وضع الكاميرا تتم معالجة الصور لدى مزوّد المسح ولا يصل هذا النظام إلا الأرقام.

## 🧠 محرّك المقاسات (`shared/engine.js`) — جوهر المنتج

المحرّك **معزول وبدون اعتماديات ويعمل بنفس الكود على الخادم وفي المتصفح**، فالرقم الذي
تراه العميلة هو نفسه الذي يحسبه الـ backend.

### المدخلات

قياسات الجسم (سم): `height`, `shoulder`, `bust`, `hip`, `sleeve`.
أي قياس غير متوفّر يُستنتج من الطول عبر نِسب تشريحية، ويُعلَّم كـ«مُقدَّر» فيخفض نسبة الدقة.

### بيانات كل عباية

لكل عباية قياساتها الخاصة (وهذا ما يجعل التوصية لكل موديل لا لجدول عام):

| الحقل | المعنى |
|------|--------|
| `lengths[]` | `{ size: 52..60, garmentLength }` — الطول من الكتف للأسفل بالسم (يحدّد وصول الطرف للأرض) |
| `widths[]` | `{ size: 'S'/'M'/'L', chest, hip }` — محيط العباية المُصنّعة بالسم |
| `fabric` | `stretch` / `non-stretch` — المطّاطي يضيف سماحية للمقاس |
| `cut` | `straight` / `a-line` / `bisht` |
| `fitType` | القصّة الافتراضية إن لم تختر العميلة |

### منطق اختيار الطول (52–60)

- نحسب ارتفاع الكتف عن الأرض ≈ `height × 0.818`.
- الطول المثالي للعباية = ارتفاع الكتف − «خلوص الطرف» حسب التفضيل:
  قياسي 2.5سم فوق الأرض · يلامس الأرض 0 · مع كعب (أطول بمقدار الكعب ~6سم) · أقصر 9سم.
- نختار الطول الأقرب، مع **معاقبة القِصَر أكثر من الطول** (طرف قصير أسوأ من طرف يلامس الأرض).

### منطق اختيار العرض (S/M/L)

- «السماحية» (ease) = محيط العباية − محيط الجسم، عند أضيق نقطة (الصدر أو الورك).
- لكل تفضيل قصّة سماحية مستهدفة: ضيّقة ~14سم · عادية ~22سم · واسعة ~34سم.
- القماش المطّاطي يقلّل محيط الجسم الفعّال بمقدار سماحية إضافية.
- نختار المقاس الأقرب للسماحية المستهدفة، مع معاقبة قوية لأي مقاس ضيّق فعلًا.

### الراحة والدقة والبدائل

- **الراحة** عند الصدر/الورك تُشتق من السماحية: ضيّق / مناسب بحدود / مريح / واسع قليلًا / واسع.
- **الدقة (confidence)** تبدأ عالية وتنخفض ببُعد الطول عن المثالي، وبعدم ملاءمة العرض،
  وبكل قياس مُقدَّر (الصدر/الورك أغلى)، وترتفع قليلًا مع المسح الحقيقي.
- **البدائل** تُحسب بإعادة تشغيل اختيار الطول لتفضيلات «يلامس الأرض / مع كعب / أقصر».

```js
const Engine = require('./shared/engine');
const { measurements } = Engine.estimateMeasurements({ height: 163, bust: 88, hip: 98 });
const rec = Engine.recommend(measurements, abaya, { hem: 'floor', fit: 'regular' });
// rec.recommended => { length: 54, width: 'S' }, rec.confidence, rec.fit, rec.alternatives
```

## 🔌 مزوّدات القياس (`shared/providers.js`)

المحرّك لا يستهلك إلا أرقامًا. المزوّد يحوّل المدخلات إلى تلك الأرقام، مما يفصل ملكية
الخوارزمية عن أي مزوّد مسح بعينه:

| المزوّد | الوصف |
|--------|-------|
| `manual` | العميلة أدخلت القياسات (يُكمل الناقص من الطول). |
| `estimate` | طول فقط (+ صدر/ورك) والباقي مُستنتج. |
| `scan` | **محاكاة** لمسح جوّال (لأغراض العرض) تستنتج قياسات منطقية من الطول على الجهاز. |
| `vendor` | نقطة ربط مزوّد حقيقي (**3DLOOK / NetVirta**). يرمي خطأً حتى يُهيّأ — عمدًا. |

استبدال المحاكاة بمزوّد حقيقي = تعديل دالة واحدة (`vendor()`) بحيث تُرجع نفس شكل القياسات.

## 🌐 واجهات الـ API

القاعدة: `/api` — كل الطلبات JSON، وCORS مفتوح للتجربة (قيّده في الإنتاج).

| الطريقة | المسار | الوصف |
|---------|--------|-------|
| GET | `/api/health` | فحص التشغيل |
| GET | `/api/abayas` | قائمة العبايات |
| GET | `/api/abayas/:id` | عباية واحدة |
| POST | `/api/abayas` | إضافة عباية (تاجر) |
| PUT | `/api/abayas/:id` | تعديل عباية (تاجر) |
| DELETE | `/api/abayas/:id` | حذف عباية (تاجر) |
| POST | `/api/recommend` | حساب التوصية |

مثال التوصية:

```bash
curl -X POST http://localhost:4100/api/recommend \
  -H 'Content-Type: application/json' \
  -d '{"abayaId":"classic-black-straight","provider":"manual",
       "input":{"height":163,"bust":88,"hip":98},
       "prefs":{"hem":"floor","fit":"regular"}}'
```

> ملاحظة: مسار `/api/recommend` يستقبل **أرقامًا فقط** ولا يستقبل أو يخزّن أي صورة.

## 🛠️ من الـ MVP إلى الإنتاج

- **ربط مزوّد مسح حقيقي** في `providers.vendor()` (3DLOOK Mobile Tailor / NetVirta).
- **قاعدة بيانات** بدل مخزن الذاكرة في `server/catalog.js` (نفس الواجهة: list/get/create/update/remove).
- **مصادقة التاجر** لمسارات الكتابة، وتقييد CORS على أصول المتجر.
- **ضبط الأرقام**: النِسب التشريحية والسماحيات في `engine.js` قابلة للمعايرة ببيانات مرتجعات حقيقية.
- **قياس الأداء**: تتبّع نسبة اعتماد التوصية ومعدّل المرتجعات قبل/بعد لإثبات القيمة للمتاجر.
